# Инструкции для агентов и разработчиков

Это демо-решение каталога МоегоСклада (Vendor API). Его читатели — вендоры и их кодовые
агенты: код отсюда берут за основу собственных решений, поэтому репозиторий оптимизирован
под копирование примеров, а не под переиспользование внутри себя.

## Как организованы примеры функционала

- Каждый крупный пример — **модуль** в своем каталоге со своим `README.md`
  (описанием модуля): назначение, карта файлов, платформенные особенности, чеклист адаптации.
- Общий код модуль трогает только в **помеченных местах**: строка или блок с комментарием
  `# [feature:<имя>]` (во фронте `// [feature:<имя>]`). Никаких реестров фич,
  событийных шин и DI: подключение — явный вызов вроде `register_loyalty(app, ...)`.
- Тесты — спецификация публичного контракта, не цель покрытия. На контракт и важный отказ хватает
  одного-двух тестов; новый тест нужен только там, где поведение не проверяет ни один существующий.
- Контракт модуля — `tests/<имя>/test_*.py`; интеграционные сценарии модуля лежат там же, docstring модуля
  говорит, что это интеграция. Группа тестов — файл, классы не вводим.
- Общая склейка приложения, HTTP и SQLite — `tests/integration/`. Фейки внешних API, `create_client()`
  и `bootstrap_iframe()` живут в `tests/conftest.py`, in-memory репозитории — в `tests/memory_repositories.py`.
- Дублировать мелкие утилиты внутри модуля можно; добавлять слои индирекции «на будущее» — нельзя.

## Навигация

- Задача **не** про Loyalty API → не открывайте `app/loyalty/**` и `frontend/src/loyalty/**`:
  базовое решение читается без них. То же для сценариев: `app/scenario/**`, `frontend/src/scenario/**`
  и `frontend/src/chat/**`.
- Нужно **взять модуль за основу** → прочитайте его `README.md` и найдите места, где он подключается к общему коду:
  `grep -rn "feature:loyalty" app/ frontend/src/`.
- Маршрут чтения базового решения: `app/services/vendor_endpoint.py` (жизненный цикл установки) →
  `app/domain/app_instance.py` (состояние) → `app/services/utils.py` (`/utils/update-settings`) →
  `app/services/entry.py` (данные страницы) → `frontend/src/iframe/IframePage.tsx` (вкладка «Основное»).

## Клиентский код

- Страница = Jinja-оболочка в `templates/entry/` + `page-data.ts` (тип данных, только типы) + React в `frontend/src/<страница>/`.
  Сервер — источник данных и авторизации, React — только представление; SPA-роутинга нет.
- UI только на `@moysklad/uikit`, импорты точечные: `@moysklad/uikit/components/<X>`. Собственный CSS —
  только `frontend/src/ui/theme.css`.
- Сборка фронта: `cd frontend && npm ci && npm run build` (в `static/assets/app`), при правках — `npm run watch`.

## Существующие модули

- `app/loyalty/` — программа лояльности: вкладка в основном iframe, `PUT .../loyalty`
  через Vendor API, заглушка провайдера Loyalty API. Описание: `app/loyalty/README.md`.
- `app/scenario/` — действия в сценариях МоегоСклада: блок `<scenario>` дескриптора, обработчик
  `POST .../scenario`, журнал срабатываний в окне чатов. Описание: `app/scenario/README.md`.
- `frontend/src/uikit-examples/` — вкладка «Примеры UI Kit»: секции-примеры компонентов кита,
  каждая — самодостаточный файл для копирования. Описание: `frontend/src/uikit-examples/README.md`.

## Команды

- `python -m compileall app tests && pytest` — обязательно перед коммитом.
- `python -m app.cli.generate_descriptor` — `descriptor.xml` в stdout.
- `python -m app` — локальный запуск (нужен `.env`, см. `README.md`).
